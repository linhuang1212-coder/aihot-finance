# 金十 / X 信源专属页 设计文档

> 网页前端 · 子功能。2026-06-14。

**Goal:** 左侧栏新增「信源」组两项 —— **金十** 和 **X**，各自打开一个**只看该信源精选条目**的页面，让用户能单独看金十快讯流 / X(KOL) 流。

**背景：** 系统当前主力信源就是金十 + X(`newsfetch.fetch_all` 只剩这两路)。前端已有 精选/全量/突发/分类 等视图，按 channel/mode/category/market/q 过滤；**缺一个按信源过滤的维度**。

---

## 锁定的设计决策

| 决策 | 选择 |
|---|---|
| 页面内容 | **只看精选**(`mode=selected`) + 该信源过滤 |
| 信源界定 | 金十 = `source == "金十"`；X = `source` 以 `"X·"` 开头(存储如 `X·Walter Bloomberg`) |
| 过滤位置 | **服务端**(filter_items 加 `source` 参数)——API 有 take=100 上限，前端筛会漏，服务端先筛再截才对 |
| 侧栏 | 「视图」组下方新增 **「信源」** 组，两项：金十、X |
| 顶部筛选 | **保留**市场 chip(A股/美股/原油…) + 「隐藏未证实」开关 + 45s 自动刷新(全部复用现有) |

## 信源匹配规则(后端)

一条通用规则同时覆盖金十(精确)和 X(前缀):

```
it.source == val  或  it.source.startswith(val + "·")
```
- `source=金十` → 命中 `"金十"`(精确)
- `source=X`   → 命中 `"X·Walter Bloomberg"` 等(前缀 `"X·"`)

## 后端(server.py)

`filter_items` 新增 `source` 参数,放进现有过滤循环:

```python
source = qs.get("source", [None])[0]
...
# 循环内,与 category/market 同级:
if source:
    s = it.get("source") or ""
    if not (s == source or s.startswith(source + "·")):
        continue
```

`/api/public/items` 自然支持 `&source=金十` / `&source=X`,无新端点。

## 前端

### index.html
「视图」`nav-group` 之后新增一组:
```html
<div class="nav-group">
  <div class="nav-group-title">信源</div>
  <a class="nav-item" data-view="source" data-source="金十">金十</a>
  <a class="nav-item" data-view="source" data-source="X">X</a>
</div>
```

### app.js
- `VIEW_TITLES` 加 `source: "信源"`;`state` 加 `source: null`;`FEED_VIEWS` 加 `"source"`(参与过滤+自动刷新)。
- `buildItemsUrl`:`else if (state.view === "source") { p.set("mode", "selected"); p.set("source", state.source); }`。
- 导航点击处理(现有 `.nav-item[data-view]` 循环)补一行 `state.source = n.dataset.source || null;`,并在切到别的视图时清掉(`state.source = null`)。
- `setActiveNav`:把 source 纳入 active 匹配(view==="source" 时比对 dataset.source === state.source)。
- `load()` 标题:`if (state.view === "source") title = state.source === "金十" ? "金十快讯" : "X · KOL";`。
- 市场 chip / 隐藏未证实 / 搜索框 / `poll()` 全部不动,自动对 source 视图生效(因为它们都走 `buildItemsUrl`)。

## 边界与降级

- 该信源暂无精选条目 → 列表空、显示现有「没有匹配的条目」。
- 搜索框输入时切到 search 视图(现有行为),`source` 被清空 —— 可接受(搜索是全局)。
- 零依赖照旧,不动卡片样式与其它视图。

## 不在本期范围

- **同事件多推合并**(同一 X 账号短时连发、讲同一事件的多条推文合并成一条)—— 另一个独立、更复杂的功能,单独走设计。
- 金十/X 之外的信源页(目前只有这两路主力)。

## 测试(TDD,stdlib unittest)

后端 `filter_items` 的 `source` 过滤(`tests/test_server_*` 或新文件,构造 ITEMS 直测):
1. `source=金十` → 只回 `source=="金十"` 的条目。
2. `source=X` → 只回 `source` 以 `"X·"` 开头的条目;`"金十"`、以及像 `"XPeng快讯"`(以 X 开头但非 `"X·"`)都不命中。(实际数据里 X 源恒为 `"X·xxx"`,不存在恰好叫 `"X"` 的源,故 `s==val` 那支对 X 形同摆设、无副作用。)
3. 无 `source` 参数 → 结果不受影响(向后兼容)。
4. `source` 与 `mode=selected` 叠加:只回该信源且 selected 的条目。

前端无 JS 测试框架(项目现状),纯展示不强测;手动验收:点「金十」「X」看流是否只剩对应信源、市场 chip/隐藏未证实/自动刷新照常。
