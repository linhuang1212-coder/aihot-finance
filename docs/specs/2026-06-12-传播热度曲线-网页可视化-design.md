# 传播热度曲线 · 网页可视化 设计文档

> 舆情系统演进 · 子项目2 续作。2026-06-12。
> 承接 2026-06-10「传播热度曲线(发酵提醒)」MVP——彼时明确 defer 的「网页端热度曲线图」本期实现。

**Goal:** 把"事件被多少家信源**累计**跟进 × 随时间"画到网页。每张多源事件卡片带一条迷你
sparkline（一眼看趋势/是否加速），点击弹大图（累计阶梯曲线 + 逐家信源传播脉络）。
复用已有 `mentions` 表，全程内联 SVG、零依赖。

**承接现状（代码探查）:**
- `mentions(group_key, source, title_zh, ts)` 已在积累"每事件每信源首报时间"（30 天保留）。
- `store.propagation()` 算滚动 90 分钟"不同信源数"→档位，server 挂 `it["propagation"]`，
  bot 推「📡 正在发酵」提醒——**已上线，本期不动（正交）**。
- 缺口：把 mentions 的"累计随时间"可视化（曲线本身）。本设计补这块。

---

## 锁定的设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 曲线含义(Y轴) | 累计不同信源数(单调↑) | "传多广 + 还在不在加速"一眼可读；停跟进就走平 |
| 露出方式 | 卡片迷你线 + 点开大图 | 列表轻量速览，下钻看脉络 |
| 数据流 | 迷你线随条目带出 + 大图走详情接口 | sparkline 跟列表秒出无额外请求；大图有逐家脉络 |
| 显示阈值 | n ≥ 2 不同信源 | 2 家即"已跨源传播"= 最早发酵信号，投资视角要趁早；做成可调常量 |
| 大图明细 | 含逐家信源加入时刻 | "谁先谁后"的传播脉络是核心价值 |
| sparkline 配色 | 按当前档位分档(中性/暖/红) | 一眼同时看形状 + 热度；复用现有徽章色 |
| 排序 | 不改(仍按 published_at) | 排序加权是另一 defer 子项目，本期不做 |

**无新表。** 复用现有 `mentions`。

## 后端

### `store.prop_series(groups=None, max_points=12, min_sources=2)`（新增）

对每个事件簇，从 mentions 算"累计不同信源数随时间"的紧凑序列。

- `groups`: 要算的 dedup_group 集合（server 传入当前 items 的 groups）；`None` = 全部窗口内。
- 每个 group：`SELECT source, ts FROM mentions WHERE group_key=? ORDER BY ts`；按 ts 升序遍历，
  维护已见 source 集合，`cum = len(集合)`（同源天然不增；mentions 主键 (group_key,source)
  已保证每家一行）。得到原始阶梯点 `[(ts, cum)]`，首点 cum=1，末点 cum=n。
- **压缩到 ≤ max_points**：在 `[first_ts, last_ts]` 上按**时间**均匀取 max_points 个采样时刻，
  每个取"该时刻为止的 cum"；保证含首(cum=1)、尾(cum=n)。跨度为 0（全在同一分钟）→
  退化为 `[[0,1],[0,n]]`。
- **仅对 `n ≥ min_sources` 的 group 返回**：
  `{group_key: {"pts": [[rel_min, cum], …], "n": n, "span_min": m, "first_ts": iso, "first_source": s}}`
  （`rel_min` = 采样时刻距 first_ts 的分钟数，给 sparkline 做 x 轴）。
- 无满足条件的 → 空 dict。

### server `refresh()` 挂载

现有 refresh 已 `prop = store.propagation()`。紧挨着加：

```python
series = store.prop_series()        # 全量算，Python 侧按 group 取（避开 SQLite IN 变量上限）
for it in items:
    s = series.get(it.get("dedup_group"))
    if s:
        it["prop_curve"] = s
```

`public_item` 透传所有非 `_` 前缀字段，`prop_curve` 随 `/api/public/items` 自动带出。

### `GET /api/public/propagation?group=<dedup_group>`（新增只读接口，大图用）

- `SELECT source, ts, title_zh FROM mentions WHERE group_key=? ORDER BY ts`。
- 逐行算 `cum`（按出现顺序累计 distinct source）。
- 返回 `{"group": g, "n": n, "first_ts": iso, "last_ts": iso, "points": [{"ts": iso, "source": s, "cum": c}, …]}`。
- group 缺失 / 无 mention → `{"group": g, "n": 0, "points": []}`。
- 复用现有 `/api/public/*` handler 风格（JSON、参数解析）。

## 前端（public/app.js, public/style.css）

### 卡片 sparkline（`cardNode` 内）

- 若 `it.prop_curve`（即 n≥2）：在 `.card-meta` 行下方插入 `.prop-row`：
  - 内联 SVG（约 88×22）`polyline`，由 `pts` 归一化：x = `rel_min` 线性映射到宽度，
    y = `cum` 映射到高度（翻转，cum 大在上）。
  - `stroke` 按 `(it.propagation?.level) || 0`：0 → 中性 `--prop-calm`；1–2 → 暖 `--prop-warm`；
    3 → 红 `--prop-hot`。
  - 右侧小字 `累计 N 家`。
  - 若 `it.propagation`（发酵中，level≥1）：行首加 `📡发酵LVx` 徽章（复用 `.badge` 样式）。
  - 整行 `cursor:pointer`，点击 → `openPropModal(it)`。

### 大图 modal（`openPropModal`）

- `fetch('/api/public/propagation?group=' + encodeURIComponent(it.dedup_group))`。
- 遮罩 + 居中面板：
  - 标题 = `it.title_zh`。
  - SVG 折线图：x = 时间（first→last，画刻度），y = 累计家数（0..n 刻度）；阶梯线（step-after）。
  - caption：`首报 {first_source} {HH:MM} · 现累计 {n} 家 · 近90分 +{k} 家`
    （k = points 中 ts 落在近 90 分钟内的新增 source 数；"仍在发酵 / 已降温"由 `it.propagation`
    有无判定）。
  - 传播脉络列表：逐行 `{HH:MM}  {source}`，最后一家高亮。
- 关闭：点遮罩、× 按钮、Esc。
- 空数据（points 为空）→ 面板显示"暂无传播数据"。

### 纯函数（无 DOM 依赖，便于人工核对/将来测试）

- `sparkPath(pts, w, h)` → 返回 SVG `points`/`path` 字符串（归一化逻辑独立）。

## 边界与降级

- 单源 / 无 mentions → 无 `prop_curve` → 卡片不显示曲线（优雅）。
- 详情接口 group 不存在 → 空 points → modal 显示"暂无传播数据"。
- **零依赖**：纯内联 SVG，无图表库、无 CDN、无构建步骤。
- bot 发酵提醒不变（正交，不碰）。
- mentions 随现有 `prune()` 同窗清理，曲线自动只覆盖近 30 天。

## 不在本期范围（MVP 边界）

- 发酵事件在精选/突发流的**排序加权**（在 `_score` 加一项）——另一 defer 子项目。
- 跨事件簇合并（两 group 实为同一事件）。
- **热度强度**（滚动窗口、会回落）曲线——本期只画累计扩散；如需可后续在大图叠加副线。

## 测试（TDD，stdlib unittest）

1. **`store.prop_series`**：
   - 3 家不同信源、不同时间 → 累计序列单调上升、末点 cum=3、含首(1)尾(3)。
   - 单源（或 < min_sources）→ 该 group 不在返回。
   - 原始点数 > max_points → 采样后 ≤ max_points 且含首尾。
   - `span_min` / `first_source` 正确。
2. **`GET /api/public/propagation`**：
   - 逐家 `cum` 递增；返回含 source 名与 ts。
   - group 缺失 → `n:0, points:[]`。
3. **server 挂载**：refresh 后 n≥2 的代表条目带 `prop_curve`，单源条目不带。
4. `prune` 清理超期 mentions 已有测试覆盖，复用。

前端无 JS 测试框架（项目现状）：纯展示不强测；`sparkPath` 抽为纯函数供人工核对/将来接入。

## 风险

- **去重质量决定曲线质量**：簇归错则 mention 记错 group——沿用现有 `DEDUP_SIM=0.5`，不在本期调。
- **阈值 n≥2 可能让多数卡片都带线**：先上 ≥2（投资要早信号），跑几天看密度；太吵则提到 ≥3
  （已留常量 `min_sources`）。
- **payload**：仅多源条目 + ≤12 个 `[int,int]`；可接受。
- **bot/server 双进程边界**：曲线只经 items API + 新只读接口传递，前端不直接读库，保持现有边界。
